# GramSoul — ролевые истории на двоих с ИИ‑рассказчиком

Нативное Android‑приложение (Kotlin + Jetpack Compose) и backend для одного VPS
(FastAPI + SQLite + Caddy; ИИ — облачные модели через OpenRouter, ключ только на сервере).
Два игрока находят друг друга по нику, играют в одной сцене, ИИ ведёт персонажей и
рассказчика и по запросу рисует фото сцены.

```
android/   приложение (один APK для обоих телефонов, package app.fonar)
deploy/site/app/  веб-версия: https://<адрес>/app/ (iPhone: «Поделиться» → «На экран „Домой“»)
server/    API: ник + пароль, друзья, персонажи, истории, сцены, очередь генераций, админка
deploy/site/admin/  админ-панель: https://<адрес>/admin/ (вход по паролю)
deploy/    docker-compose, Caddyfile, установка/обновление/бэкап для Debian 13
tools/     сценарий двух эмуляторов (adb + uiautomator)
.github/   сборка APK, тесты, тест на двух эмуляторах, деплой на VPS
```

## Как это устроено

* **Вход** — ник (3–20 символов: латиница, кириллица, цифры, `_` и `.`) и пароль (6–128 символов),
  экраны «Регистрация» и «Вход». Уникальность и поиск — по нормализованному нику: регистр
  не важен, `ё` = `е`, кириллические буквы‑двойники латинских (`М`/`M`, `а`/`a`…) считаются
  одной буквой. Пароль хранится только как хэш scrypt; на неверный ник и неверный пароль —
  одна и та же ошибка, попытки ограничены (10 за 10 минут с адреса, 10 в час на ник).
  Сервер выдаёт случайный токен (в базе только его хэш); на телефоне он зашифрован
  ключом AES‑GCM из Android Keystore. Аккаунты, созданные до паролей, при первом запуске
  новой версии (Android и веб) видят только экран «Придумай пароль», пока не зададут его.
  Пароль меняется в профиле (нужен старый).
* **Код переноса** — вход с другого телефона: в профиле создаётся одноразовый код на 10 минут
  (`ABCD-EFGH`, в базе хэш, 5 попыток), на новом телефоне — ник + код.
* **Профиль** — ник, аватар и «о себе» (необязательно), код переноса (нажатие копирует его),
  смена пароля, списки «Мои персонажи / Мои истории / Мои чаты» с удалением, выход.
* **Друзья** — поиск по началу или части ника (от 2 символов, до 20 результатов, с лимитом
  запросов), заявка → принята / отклонена, в списке друзей — «в сети» по последней активности.
* **Персонажи** (вкладка «Персонажи», простой режим) — имя (60), первое сообщение (5000),
  описание (10000), видимость «Публичный / Личный», в доп. настройках предыстория и характер
  (по 2000, видны только автору — их получает ИИ) и теги. Черновик или публикация, поиск по
  имени и `#тегу`. «Придумать с ИИ» заполняет поля по короткой идее. 6 оригинальных
  демо‑персонажей. Все персонажи — 18+.
* **Личный чат с персонажем** — «Начать чат» на странице персонажа. Первое сообщение — всегда
  его приветствие; ответы стримятся; ИИ пишет только за персонажа и отвечает на последний ход
  игрока: коротко (обычно 1–4 предложения), действия и мысли `*в звёздочках*`, реплики с тире.
  В чате мысли и действия идут курсивом прямо на чёрном фоне, а каждая реплика — отдельным
  пузырём (их может быть несколько подряд); пузыри не доходят до противоположного края.
  Над полем ввода — белые иконки: ✎ изменить последний ответ, ✦ 3 варианта следующей реплики,
  ↻ перегенерировать, ⏩ продолжить; справа 📷 — одним нажатием нарисовать, что сейчас
  происходит (место и персонажи по их описаниям и аватарам; долгое нажатие — своё описание)
  и 🖼 — отправить своё фото. Кнопка `*` в поле ввода ставит пару звёздочек с курсором
  между ними. Долгое нажатие на сообщение — исправить его. Старая часть переписки
  сворачивается в краткую сводку (память), вся история хранится целиком.
* **Свои фото в чате** — игрок отправляет фото из галереи (до 6 МБ, сжимается до 1600 px,
  лимит `RL_CHAT_PHOTOS_PER_HOUR`=20 в час). Фото хранится `CHAT_PHOTO_TTL_DAYS`=7 дней и
  удаляется автоматически; на его месте в чате остаётся короткая пометка.
* **AI‑аватар 2:3** — загрузка из галереи или генерация: описание внешности + стиль
  (Аниме, Реализм, Нарисованный, Манхва, Ч/б рисунок). Промпты стилей хранятся только на
  сервере; описание сначала превращается текстовой моделью в короткое визуальное описание
  взрослого персонажа, затем рисует модель изображений. Описание можно не писать: достаточно
  имени известного персонажа («Лелуш Ви Британия из аниме Код Гиасс»). Лимит —
  `RL_AVATARS_PER_DAY` (20) в сутки.
* **Истории** — быстрое создание (имя, аватар, характер, речь, стартовая реплика)
  и полный редактор: обложка, описание, вступление, правила мира, стартовая сцена,
  до 10 персонажей (до 2 из них — герои игроков), стартовые сообщения от
  рассказчика и любых персонажей. Черновики сохраняются на телефоне.
* **Сцена** — у комнаты два места: хозяин и приглашённый друг. Каждый ведёт своего
  героя, ИИ — остальных персонажей и рассказчика. Действия `*в звёздочках*`
  показываются курсивом, рассказчик — отдельным блоком.
* **Карточка персонажа** открывается из чата по аватару или имени; хозяин правит её
  и возвращается в сцену. Правка действует со следующей генерации у обоих.
  Начатая генерация использует ту версию карточек, с которой стартовала.
* **Контекст модели**: актуальные карточки, правила мира, состояние сцены (место,
  кто рядом, недавние действия), краткое резюме старой переписки и последние
  сообщения. Вся переписка хранится в базе целиком.
* **Синхронизация** — long‑poll по номеру ревизии: после обрыва связи телефон
  получает всё пропущенное. Сообщения упорядочены сервером, повтор отправки
  (тот же `client_id`) не создаёт дубль. Одна генерация ИИ на весь сервер.
* **Ошибки модели** не теряют ход игрока и предыдущий ответ; в чате появляется
  «Повторить генерацию».
* **Доступ**: любые данные сцены (сообщения, карточки, картинки, промпт)
  отдаются только двум участникам; чужим — 404.

## Веб-версия и iPhone

`https://<адрес-сервера>/app/` — то же приложение в браузере: вход по нику и паролю или коду переноса,
персонажи (создание с ИИ и AI-аватар), личные чаты и сцены с друзьями (стриминг, правка ответа ИИ,
варианты реплики, фото сцены), друзья и профиль. Аккаунт общий с Android.
На iPhone: открыть адрес в Safari → «Поделиться» → «На экран „Домой“» — GramSoul появится иконкой
и будет открываться на весь экран. Отдельной сборки не нужно: файлы лежат в `deploy/site/app`
и обновляются вместе с сервером (`update.sh`). Проверка: workflow **Web app** (iPhone-размер, Chromium).

## Установка backend на VPS (Debian 13, 1 vCPU, 2 ГБ)

### Вариант А — одна команда в консоли VPS

Открой консоль VPS (веб‑консоль хостера или SSH‑приложение на телефоне) и выполни:

```bash
curl -fsSL https://raw.githubusercontent.com/neezzq/GramSoul/refs/heads/claude/great-keller-r937dd/deploy/install.sh | bash
```

Все команды для VPS в этом файле даны для входа под `root` (так обычно и бывает на VPS).
Если входишь обычным пользователем, добавляй в начало `sudo`.

Скрипт поставит Docker, создаст swap 2 ГБ, скачает код в `/opt/fonar`, получит
HTTPS‑сертификат (адрес вида `1-2-3-4.sslip.io`, если нет своего домена) и включит
ночной бэкап.
В конце он печатает адрес сервера — его нужно вписать в сборку APK.

Свой домен: `... | bash -s -- --domain fonar.example.com` (A‑запись домена → IP VPS).
Порты 80 и 443 должны быть открыты у хостера.

### Вариант Б — из GitHub Actions

В репозитории: **Settings → Secrets and variables → Actions** добавь секреты
`VPS_HOST` (IP), `VPS_PASSWORD` (или `VPS_SSH_KEY`), при необходимости `VPS_USER`,
`VPS_PORT`; переменную `DOMAIN` — если есть свой домен. Затем **Actions → Deploy to
VPS → Run workflow**. После установки workflow сам проверяет публичный HTTPS‑API
сценарием двух игроков.

### Облачный ИИ и фото сцены (OpenRouter)

Ключ OpenRouter хранится **только на сервере** (в APK его нет: из APK любой мог бы
достать ключ и тратить твой баланс). Установка ключа — одной командой на VPS:

```bash
bash /opt/fonar/deploy/set-openrouter-key.sh
```

Скрипт спросит ключ (`sk-or-…`, ввод не отображается), проверит его в OpenRouter,
сохранит в `/opt/fonar/deploy/.env` (доступ только root) и перезапустит API.
После этого:

* все ответы, варианты реплик, сводки и аватары идут через облачную модель;
* кнопка 📷 над полем ввода — «Фото сцены»: модель изображений рисует текущий
  момент (долгое нажатие — подсказать, что показать), картинку видят оба игрока.

Модели по умолчанию (меняются в `.env`, пересборка APK не нужна):

| Переменная | По умолчанию | Примерная цена |
|---|---|---|
| `CLOUD_TEXT_MODEL` | `deepseek/deepseek-v4.1-flash` | доли цента за ответ |
| `CLOUD_IMAGE_MODEL` | `google/gemini-3.1-flash-lite-image` | ~3–4 цента за картинку |
| `RL_IMAGES_PER_DAY` | 30 | лимит фото на игрока в сутки |

### Настройки модели

`/opt/fonar/deploy/.env`: `CLOUD_TEXT_MODEL`, `CLOUD_IMAGE_MODEL`, `CLOUD_MAX_TOKENS` (450 —
держит ответы короткими), `CLOUD_TEMPERATURE`, таймауты, лимиты частоты запросов. После правки:
`cd /opt/fonar/deploy && docker compose up -d`.

Маленькая локальная модель (Ollama, `qwen2.5:0.5b`) выключена: отвечала слишком глупо.
`update.sh` останавливает её контейнер и освобождает ~700 МБ памяти. Вернуть можно строкой
`LOCAL_AI=on` в `.env` и `update.sh` — тогда в сценах снова появится переключатель ИИ.

### Админ-панель

`https://<адрес>/admin/` — все зарегистрированные игроки: токены на текст, токены и число
аватаров, фото сцен, персонажи, чаты, стоимость в OpenRouter (с итогами), и вкладка
«Фото игроков» — все свои фото из чатов с ником, чатом и датой автоудаления; любое можно
удалить сразу. Вход — только по паролю. Задать или сменить пароль (на VPS, ввод не отображается,
минимум 10 символов):

```bash
bash /opt/fonar/deploy/set-admin-password.sh
```

В `.env` сохраняется только хэш scrypt (`ADMIN_PASSWORD_HASH`); без него `/v1/admin/*` отвечает 404.
Вход в админку — 5 попыток за 15 минут с адреса, сессия живёт 12 часов.

Замер скорости и памяти в любой момент: `bash /opt/fonar/deploy/bench.sh`.

## Сборка APK

Адрес backend вшивается при сборке (в приложении нет полей для сервера).
Ключ подписи хранится **вне репозитория**.

Через GitHub Actions (workflow **Android**) нужны секреты:

| Секрет / переменная | Что это |
|---|---|
| `BACKEND_URL` (переменная или секрет) | `https://…` — адрес, который напечатал install.sh |
| `ANDROID_KEYSTORE_B64` | содержимое файла `fonar-release.p12.base64.txt` |
| `ANDROID_KEYSTORE_PASSWORD` | пароль из `keystore.properties` |
| `ANDROID_KEY_ALIAS` | `fonar` |
| `ANDROID_KEY_PASSWORD` | тот же пароль |

Каждый push в `android/` собирает подписанный APK и публикует его как релиз.
(Внутренний package — `app.fonar`: он не меняется, чтобы обновления вставали поверх.)
Постоянная ссылка для скачивания с телефона:
`https://github.com/neezzq/GramSoul/releases/latest/download/GramSoul.apk`.
Тот же файл раздаёт сам сервер: `https://<адрес-сервера>/fonar.apk`
(страница `https://<адрес-сервера>/` — для друга).

Локально (нужен Android SDK):

```bash
cd android && FONAR_BACKEND_URL=https://<адрес> FONAR_KEYSTORE_PATH=/путь/fonar-release.p12 \
  FONAR_KEYSTORE_PASSWORD=... FONAR_KEY_ALIAS=fonar ./gradlew assembleRelease
```

**Обновления** ставятся поверх старой версии с сохранением входа, пока не меняются
package `app.fonar` и ключ подписи. Потеряешь ключ — новую версию придётся ставить
после удаления старой, а все ники станут недоступны. Храни `fonar-release.p12` и
пароль в двух местах (например, облако + менеджер паролей).

## Обновление backend

```bash
bash /opt/fonar/deploy/update.sh
```

Делает бэкап, подтягивает код, пересобирает контейнеры, обновляет сайт, веб-версию,
админку и APK для страницы скачивания. Данные и настройки остаются.

## Бэкап и восстановление

* Автоматически каждую ночь в 04:17: `/opt/fonar/deploy/backups/fonar-*.tar.gz`
  (база SQLite через online‑backup + картинки), хранятся последние 14.
* Вручную: `bash /opt/fonar/deploy/backup.sh`.
* Скачать копию к себе: `scp root@<IP>:/opt/fonar/deploy/backups/fonar-<дата>.tar.gz .`
* Восстановить: `bash /opt/fonar/deploy/restore.sh backups/fonar-<дата>.tar.gz`.

Сессии игроков хранятся в базе, поэтому после восстановления из свежего бэкапа
телефоны продолжают работать без повторной регистрации.

## Тесты

```bash
cd server && pip install -r requirements-dev.txt && pytest -q          # API, фейковая модель
python3 server/tests/e2e_live.py https://<адрес>                       # живой сервер и модель
cd android && FONAR_TEST_BACKEND=http://127.0.0.1:8001 ./gradlew testDebugUnitTest   # UI (Robolectric)
```

Workflow **Emulators (two phones)** запускает два чистых эмулятора Android 14 с
одним и тем же (минифицированным) APK и проходит весь сценарий двух игроков с локальной
заменой OpenRouter (`tools/mock_openrouter.py`, без настоящего ключа); скриншоты — в артефактах
запуска. Workflow **Web app** проверяет веб-версию и админку в Chromium размера iPhone.

Что именно проверено и где (локально, в GitHub Actions, на VPS, на телефонах) —
в [docs/VERIFICATION.md](docs/VERIFICATION.md).
